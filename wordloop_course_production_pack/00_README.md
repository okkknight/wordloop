# WordLoop AI 课程生产包

## 1. 目标

本生产包用于批量制作 WordLoop 的英语句子跟读课程。

每门课程默认包含 16 个可独立朗读的英文句子，覆盖 A2—B2，面向希望提高日常交流、沟通能力和个人表达能力的成年英语学习者。

这套流程的核心不是让 AI 直接“写 16 句话”，而是让 AI 依次完成：

1. 规划整个课程池；
2. 设计单门课程的能力目标、内容结构和难度曲线；
3. 按句子槽位生成候选句；
4. 结合程序检查结果完成审稿和最终组课；
5. 由人类进行快速检查与最终批准。

## 2. 最终落地形态

```text
Prompt 0：课程体系规划器
        ↓
AI 自审并修订课程池
        ↓
人工检查：选题、类型、等级、重复与覆盖
        ↓
Prompt 1：单课蓝图生成器
        ↓
人工检查：学习目标、核心表达、难度与句子槽位
        ↓
Prompt 2：候选句生成器
        ↓
确定性检查程序
        ↓
Prompt 3：课程审稿与组课编辑器
        ↓
人工终审最终 16 句
```

## 3. 文件说明

- `01_GLOBAL_CONTENT_STANDARD.md`：所有 Prompt 共同遵守的内容标准。
- `02_PROMPT_0_CURRICULUM_PLANNER.md`：批量生成课程选题、类型与等级。
- `03_PROMPT_1_COURSE_BLUEPRINT.md`：生成单门课程简报、难度蓝图和 16 个句子槽位。
- `04_PROMPT_2_CANDIDATE_GENERATOR.md`：每个槽位生成多个候选句。
- `05_PROMPT_3_REVIEWER_EDITOR.md`：审稿、选句、有限改写和最终组课。
- `06_CHECKER_SPEC.md`：交给 Codex 实现的确定性检查程序要求。
- `07_CODEX_ORCHESTRATION_PROMPT.md`：让 Codex 搭建并执行整条流水线的总指令。
- `schemas/`：各阶段推荐使用的 JSON Schema。
- `examples/production_config.example.json`：生产配置示例。

## 4. 三种课程原型

### 4.1 场景交互型 `scenario_interaction`

目标：在一个现实情境中完成具体任务。

典型主题：点餐、入住酒店、看医生、退换商品、问路、预约服务。

常见结构：

```text
进入场景 → 提出需求 → 补充或修改需求 → 处理情况 → 确认并结束
```

### 4.2 沟通功能型 `communication_skill`

目标：掌握一种可以跨场景迁移的沟通动作。

典型主题：礼貌拒绝、请求重复、提出建议、澄清误会、表达不同意见。

常见结构：

```text
直接表达 → 礼貌表达 → 语气变化 → 补充理由 → 复杂情境表达
```

### 4.3 主题表达型 `topic_expression`

目标：围绕一个主题描述自己、解释原因或表达观点。

典型主题：我的周末、工作习惯、旅行偏好、学习英语、对人工智能的看法。

常见结构：

```text
直接陈述 → 具体细节 → 原因与偏好 → 对比与变化 → 完整观点
```

上述结构是参考原型，不是必须硬套的固定阶段。任何阶段如果不服务于课程目标，都应被删除、合并或替换。

## 5. 难度设计原则

课程等级由“用户学完后能完成什么表达任务”决定，不由平均句长或主题表面难易决定。

每门课程内部使用三个难度层级：

```text
A2 课程：A2- → A2 → A2+
B1 课程：A2+ → B1 → B1+
B2 课程：B1+ → B2 → B2+
```

默认 16 句分布：

- 3 句进入难度；
- 4 句目标基础；
- 6 句目标主体；
- 3 句目标挑战。

采用波浪式递进，而不是 16 句持续直线上升。最后一句强调完整、自然和可迁移，不要求成为全课最难句。

## 6. 人类审核原则

人类不是从空白开始设计课程，而是做编辑和质检。

### 课程池阶段

检查：

- 选题是否值得做；
- 类型与学习目标是否一致；
- 等级是否由任务复杂度合理推导；
- 是否与现有课程重复；
- 整个课程池是否失衡。

### 蓝图阶段

检查：

- 学完后用户到底能说什么；
- 核心表达是否值得重复；
- 16 个槽位是否各有价值；
- 难度曲线是否平滑；
- 是否出现为了套模板而存在的内容。

### 最终课程阶段

检查：

- 句子是否自然、实用、可独立朗读；
- 是否存在教材腔或填充句；
- 重复是否具有学习价值；
- 课程结尾是否形成完整表达能力。

## 7. 最重要的生产原则

> 先设计能力，再设计句子角色；先生成候选，再选择成课；程序检查形式，AI 检查语言，人检查价值。

## 8. 当前实现：候选句检查器

仓库已实现生产流水线的第一步：候选句确定性检查器。它读取课程蓝图、候选句和可选生产配置，输出 JSON 报告；存在 error 时以非零状态退出。它不判断英语自然度、课程价值或精确 CEFR，这些仍由 Prompt 3 和人工终审负责。

```bash
npm run course:check -- \
  --blueprint outputs/course-blueprint.json \
  --candidates outputs/candidate-sentences.json \
  --config wordloop_course_production_pack/examples/production_config.example.json \
  --report outputs/checker-report.json
```

检查器覆盖 Schema、16 个槽位和候选数量、词数（缩写与连字符各计一词）、标点/异常字符、重复、高相似度、required/core chunk 覆盖、粗略分句数、模型自报字段，以及蓝图的难度曲线。错误阻止进入 Prompt 3；警告保留给编辑判断。
